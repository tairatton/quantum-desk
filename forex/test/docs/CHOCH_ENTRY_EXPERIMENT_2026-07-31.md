# CHoCH Entry Experiment — 2026-07-31

**คำถาม:** ถ้าให้บอทเปิดออเดอร์ตอนเกิด CHoCH จะทำให้ระบบเก็บกำไรได้ไวขึ้นไหม
และถ้าจำกัดให้เข้าเฉพาะตอนที่กติกาเดิมยังไม่มีออเดอร์ จะดีขึ้นไหม

**คำตอบสั้น:** ไม่ ทั้งสองแบบ — ไม่เร็วขึ้นอย่างมีนัยสำคัญ และผลตอบแทนแย่ลง
**ยังไม่มีการแก้โค้ดใด ๆ ใน repo จากการทดลองนี้**

---

## วิธีทดสอบ

รัน state machine ตัวเดียวกับ `xau/quantum.py` (`_features` + ลูป `analyse`)
แต่สลับ "กติกาเข้าไม้" ได้ สคริปต์ทดลองอยู่นอก repo (scratchpad `choch_test.py`)

| โหมด | กติกาเข้า |
|---|---|
| `baseline` | กติกาที่บอทใช้จริง: BOS/CHoCH → หน้าต่าง 8 แท่ง (`SETUP_WINDOW`) → ต้อง score ≥ 6 + trend ผ่าน → เข้าที่ close หรือรอ retrace 50% |
| `break_now` | สัญญาณเดิมทุกอย่าง แต่ยิง market ทันที ไม่รอ retrace |
| `choch_filt` | เข้าที่แท่ง CHoCH ทันที แต่ยังกรอง score ≥ 6 + trend |
| `choch_raw` | เข้าที่แท่ง CHoCH ทันที ไม่กรองอะไรเลย |
| `hybrid_N` | ใช้กติกาเดิมเป็นหลัก; ถ้าไม่มีออเดอร์ค้าง **และว่างมาแล้ว ≥ N แท่ง** ค่อยให้ CHoCH เข้าแทน (ทดสอบ N = 0, 20, 50) |

**ข้อมูล:** XAUUSD / EURUSD / BTCUSD, M30 + M15, 50,000 แท่ง (2022-05 → 2026-07)
จาก `data/market/` — BTCUSD มีแค่ ~6,000 แท่ง (ตัวอย่างน้อย ใช้อ้างอิงอย่างระวัง)

**การคิดผล:** แบ่งไม้ 3 ส่วนออกที่ TP1/TP2/TP3 หักสเปรด + คอมมิชชั่น + slippage
ตาม `config.COSTS` (ใช้ `technique_lab._cost_r`)

### หมายเหตุสำคัญเรื่องวิธีนับ R

รายงานนี้ใช้ **mark-to-market**: ไม้ที่ถูกตัดกลางทาง (INVALIDATED / TIMEOUT)
คิดกำไร-ขาดทุนจริงตามราคาปิดของแท่งที่ปิดไม้

ต่างจาก `analyse()` ใน repo ที่นับไม้ค้างเหล่านี้เป็น **0R** ความต่างนี้สำคัญมาก
เพราะ `choch_raw` โดนตัดกลางทางถึง 42% ของไม้ทั้งหมด ถ้านับแบบ 0R มันจะดูเหมือน
ทำกำไรได้ +173R บน XAUUSD M30 ซึ่งเป็นภาพลวง — พอนับตามราคาจริงเหลือ −14.7R

### ข้อสรุปที่ 1

1. **เร็วขึ้นจริง แต่น้อย** — ถือสั้นลง 25.5 → 20.8 แท่ง (−18%), ถึง TP1 เร็วขึ้น
   14.3 → 12.8 แท่ง (−10%) บน M30 คือประมาณ 45 นาทีต่อไม้ ไม่ใช่ก้าวกระโดด
2. **SL% ที่ลดจาก 50% → 29% ไม่ใช่ความแม่นยำ** — เป็นเพราะไม้ 42% ถูก CHoCH
   สวนทางตัดทิ้งก่อนถึง SL ไม่ใช่เพราะเข้าไม้ได้ดีขึ้น
3. **คุณภาพไม้แย่ลง** — TP3% ลด 32.2 → 28.6, TP1% ลด 50.0 → 47.0
   ตัวกรอง score ≥ 6 ทำงานของมันอยู่จริง
4. **ไม่สม่ำเสมอข้ามตลาด** — XAUUSD M15 แย่ลงเกือบ 5 เท่า

### ข้อสรุปที่ 2

1. **ไม้ fallback ขาดทุนทุกตลาด ทุก timeframe ไม่มีข้อยกเว้น** — เฉลี่ย −0.16 ถึง
   −1.22 R ต่อไม้ ขณะที่ไม้ปกติของ baseline อยู่แถว −0.03 R
   คือ **แย่กว่าไม้ปกติราว 5–10 เท่า**
2. **ไม่ได้เร็วขึ้นด้วยซ้ำ** — `avg_bars_to_TP1` ไม่ขยับเลย (14.3 → 14.3 บน XAU M30)
   ไม้ปกติยังใช้เวลาเท่าเดิม แค่มีไม้ขาดทุนแถมมาคั่นกลาง
3. **ยิ่งตั้งเงื่อนไขยากขึ้น ผลยิ่งเข้าใกล้ baseline** — `hybrid_50` เหลือ 7 ไม้บน
   XAU M30 และผลเกือบเท่า baseline พอดี จุดที่ดีที่สุดของสเกลนี้คือ "ไม่เพิ่มเลย"
4. **max DD แย่ลงชัด** — XAUUSD M30: 94.7 → 115.5 R

### ทำไมถึงเป็นแบบนี้

CHoCH ที่ baseline ไม่เข้า ไม่ได้ถูกข้ามโดยบังเอิญ — มันถูกข้ามเพราะ score < 6
หรือ trend ไม่ผ่าน ซึ่งคือ CHoCH ที่ไม่มี momentum หนุน และช่วงที่บอทว่างนาน ๆ
มักเป็นช่วง sideway / ก่อนข่าว ซึ่งเป็นช่วงที่ CHoCH หลอกมากที่สุดพอดี
การ "ว่างแล้วเข้าไปก่อน" จึงเท่ากับไปเก็บเฉพาะไม้ที่ระบบคัดทิ้งไว้แล้ว

## สรุปรวม

**ไม่แนะนำให้เปลี่ยน** ทั้งแบบเข้าทุก CHoCH และแบบ fallback ตอนว่าง
ทำแล้วผลตอบแทนแย่ลงและ drawdown สูงขึ้น โดยแทบไม่ได้ความเร็วเพิ่มเลย

**ทางที่น่าลองต่อ ถ้าปัญหาจริงคือ "บอทว่างนานเกินไป":**

- ลด threshold จาก score ≥ 6 → 5 โดยยังคงตัวกรอง trend ไว้ (ยังไม่ได้ทดสอบ)
- `break_now` — สัญญาณเดิมทั้งหมด แค่ไม่รอ retrace 50% ได้ fill 100% แทนที่จะ
  หลุดไป 16% บน BTCUSD M30 ทำได้ดีกว่า baseline แต่ตลาดอื่นยังไม่ชนะ

**หมายเหตุ:** ตัวเลข baseline ในรายงานนี้ติดลบทุกตลาดเพราะใช้ mark-to-market
ซึ่งเข้มกว่าวิธีนับของ repo — ประเด็นของรายงานคือ *การเปรียบเทียบ* ระหว่างโหมด
ไม่ใช่ตัวเลขผลตอบแทนสัมบูรณ์ของระบบ
